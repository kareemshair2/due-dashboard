# DUE — Operations Intelligence Dashboard

لوحة تشغيل عربية (RTL) لشركة **DUE – Delivery Ultimate Express**، تقرأ ثلاث تبويبات من Google Sheets وتعرض مؤشرات الطلبات والفروع والعربات وجودة البيانات. اللوحة **للقراءة فقط** ولا تكتب في الشيت.

- الواجهة: JavaScript ES Modules + Vite، بدون إطار عمل.
- الرسوم: Chart.js.
- الأيقونات: Lucide.
- الخط: IBM Plex Sans Arabic.
- التخزين المؤقت: IndexedDB.
- الاختبارات: Vitest (101 اختبارًا).
- النشر: GitHub Pages + وكيل Google Apps Script اختياري.

## التشغيل السريع

المتطلبات: Node.js 22 أو أحدث.

```powershell
npm.cmd install
npm.cmd run dev
```

ثم افتح `http://127.0.0.1:5173/`.

> على Windows استخدم `npm.cmd` إذا كانت سياسة التنفيذ تمنع `npm.ps1`.

## إعداد مصدر البيانات

يوجد مزوّدان، ويُختار بينهما من `js/config.js`:

### 1. gviz — للتطوير المحلي

```js
export const config = {
  provider: "gviz",
  spreadsheetId: "15V6Lvg9cqBb7xsT6Z4vS7nn6RRRm_JVd5eytqKaLvt8",
  // ...
};
```

`gviz` يقرأ الشيت مباشرة من المتصفح. مناسب للتطوير فقط لأن رقم الشيت يظهر في الواجهة.

### 2. Apps Script Proxy — للإنتاج

اتبع `scripts/apps-script/README.md` لنشر Web App للقراءة فقط، ثم:

```js
export const config = {
  provider: "apps-script",
  spreadsheetId: "15V6Lvg9cqBb7xsT6Z4vS7nn6RRRm_JVd5eytqKaLvt8",
  appsScriptUrl: "https://script.google.com/macros/s/XXXX/exec",
  // ...
};
```

مزايا الوكيل:

- صلاحية `spreadsheets.readonly` فقط.
- لا يوجد Service Account private key ولا client secret في الواجهة أو المستودع.
- رقم الشيت مدمج كقيمة افتراضية داخل `Code.gs`، ويمكن تجاوزه بأمان عبر `SPREADSHEET_ID` في Script Properties.
- تحويل خلايا التاريخ إلى `yyyy-MM-dd` لتجنّب غموض `D/M` و`M/D`.
- تخزين مؤقت عبر `CacheService`.

`js/config.js` مستبعد من Git. للنشر الآلي يُولَّد من متغيرات المستودع:

| الاسم | النوع | مطلوب |
| --- | --- | --- |
| `DUE_SPREADSHEET_ID` | Variable | نعم |
| `DUE_PROVIDER` | Variable | لا (الافتراضي `apps-script`) |
| `DUE_APPS_SCRIPT_URL` | Secret | نعم مع `apps-script` |
| `DUE_SHEET_ORDERS` | Variable | لا |
| `DUE_SHEET_BRANCHES` | Variable | لا |
| `DUE_SHEET_CARS` | Variable | لا |

## الصفحات

| الصفحة | المحتوى |
| --- | --- |
| نظرة عامة | KPIs مجمّعة، رسم الطلبات، توزيع الحالات، أعلى الفروع، ملخص العربات، رؤى محسوبة |
| الطلبات | KPIs، رسم يومي، توزيع الحالات، أعلى العملاء، جدول قابل للفرز والتصدير |
| الفروع والوكلاء | KPIs، ترتيب الفروع، حصة كل فرع، صفوف بدون PICK UP، سجل `Hold` الاستثنائي |
| العربات | المسافة والرحلات والوقود والتكلفة، كفاءة الوقود، جدول السجلات غير الصالحة |
| جودة البيانات | ملاحظات مصنّفة (حرجة/تحذير/ملاحظة)، تصفية، جدول تفصيلي |
| الإعدادات | المظهر، التحديث التلقائي، مدة التخزين المؤقت، معلومات المصدر، تصدير/طباعة |

كل صفحة لها فلاتر مستقلة تؤثر على KPIs والرسوم والجداول والرؤى، مع شرائح قابلة للإزالة وفلاتر تاريخ جاهزة.

## قواعد البيانات المطبّقة

### التواريخ

- تُقرأ قيم gviz من نوع `Date(y,m,d)` مباشرة.
- تُقرأ قيم Apps Script بصيغة `yyyy-MM-dd`.
- التواريخ النصية الغامضة مثل `11/9/2026` تُفسَّر حسب `dateOrder` (`DMY` افتراضيًا) وتُعلَّم كغامضة في جودة البيانات.

### المسافة والعدادات

لا تُستخدم قيمة `عدد الكيلوات` كمسافة موثوقة. تُحسب المسافة كالتالي:

```
distance = end - start
```

فقط إذا تحققت كل الشروط:

1. القراءتان موجودتان.
2. كلتاهما غير سالبة.
3. `end >= start`.
4. ليستا صفرًا معًا.

غير ذلك: `distance = null`، ويُسجَّل السبب في جودة البيانات. أي اختلاف بين `عدد الكيلوات` والمسافة المحسوبة يظهر كتحذير.

### الحالات والفروع

- `PICK UP` تُوحَّد إلى `PICK_UP`.
- `Hold` تُوحَّد إلى `HOLD`.
- أي حالة أخرى تُصنَّف `OTHER` وتظهر كتحذير.
- الفرع `Hold` سجل استثنائي: يُستبعد من مؤشرات الفروع ويُعرض منفصلًا، ولا يُحتسب ضمن إجمالي PICK UP للفروع.

### الكميات

`عدد PICK UP` في تبويب الفروع يُعامل ككمية، وليس كعدد سجلات. إجمالي الفروع الحالي (18) يطابق كمية PICK UP في الطلبات (18).

## النشر على GitHub Pages

1. ارفع المشروع إلى مستودع GitHub.
2. من **Settings → Pages** اختر **GitHub Actions** كمصدر.
3. أضف المتغيرات والسر من **Settings → Secrets and variables → Actions**.
4. ادفع إلى `main`، أو شغّل `Deploy to GitHub Pages` يدويًا.

سير العمل:

- `.github/workflows/ci.yml`: فحص الأنواع والاختبارات عند كل PR/دفع إلى `main`.
- `.github/workflows/deploy.yml`: فحص + اختبار + توليد الإعداد + بناء + نشر `dist/`.

المشروع يستخدم `base: "./"` وHash Router، لذلك يعمل على مسار المستودع دون إعداد إضافي.

## الأمان

- لا توجد مفاتيح Service Account أو أسرار OAuth في الواجهة.
- لا توجد استدعاءات كتابة إلى Google Sheets.
- وكيل Apps Script يستخدم `spreadsheets.readonly` فقط.
- رابط Web App يعمل كبيانات اعتماد: من يملكه يمكنه قراءة التبويبات. لا تنشره ولا تلتقطه في الصور.
- عند تسريب الرابط: أرشف النشر القديم، أنشئ نشرًا جديدًا، وحدّث `DUE_APPS_SCRIPT_URL`.
- سياسة CSP في `index.html` تحدّ من المصادر المسموح بها.

## ملاحظات معروفة

1. **التواريخ:** تاريخ الشيت هو المرجع النهائي، ولا يُعدّل من الواجهة. الوكيل يحوّل التواريخ إلى `yyyy-MM-dd` فلا يوجد غموض في الإنتاج؛ وفي وضع gviz المحلي تُفسَّر التواريخ النصية الغامضة حسب `dateOrder`.
2. **الشعار:** تم اعتماد الشعار الرسمي (`public/logo.jpeg`)، ويُستخدم نفسه كأيقونة للموقع.
3. **`عدد PICK UP`:** معامل ككمية بناءً على تطابق الإجمالي مع كميات الطلبات. إذا كان المقصود عدد سجلات، يجب تغيير الدلالة في التحليلات.
4. **البيانات الحقيقية الحالية:** 4 طلبات، 6 صفوف فروع، 3 سجلات عربات. لا توجد بيانات وهمية في الإنتاج.
